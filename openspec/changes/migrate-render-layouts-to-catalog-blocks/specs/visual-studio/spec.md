# Spec Delta

## MODIFIED Requirements

### Requirement: Authoring is two-stage

For every infographic-family type the system SHALL first produce a typed **content spec** as data, and MUST derive the rendered markup deterministically from that spec. The model MUST NOT author the markup. The spec SHALL carry the title, the ordered labelled blocks with their values, the accent, the motion kind and the duration; a spec missing required fields MUST fail loudly rather than render a partial asset.

The composition source SHALL be a set of **versioned, pre-installed templates** rather than caller input: a render MUST NOT execute markup, script or style supplied in a request. Templates SHALL be installed into the render image at build time at a pinned version and MUST be able to render with no outbound network, so the same spec and the same image produce the same composition.

A template MAY be a catalog block that declares its own typed variables. When it does, the system SHALL map spec fields onto those declared variables, SHALL only pass values of the declared type, and SHALL fall back to the template's declared default for any variable the spec does not supply. A spec field a template does not declare MUST be ignored rather than injected.

#### Scenario: Spec then markup
- **WHEN** an infographic-family asset is produced
- **THEN** a content spec exists first
- **AND** the rendered markup is generated by deterministic code from that spec

#### Scenario: Invalid spec
- **WHEN** the produced spec is missing a required field
- **THEN** the run fails naming the missing field
- **AND** no markup or image is produced for it

#### Scenario: Caller markup is refused
- **WHEN** a request carries HTML, CSS or script rather than a spec
- **THEN** the request fails without rendering

#### Scenario: Offline and pinned
- **WHEN** a composition is rendered
- **THEN** every template it uses was installed in the image at build time
- **AND** no network request is made to fetch a template, a script or a font

#### Scenario: A template's declared variables are respected
- **WHEN** a spec supplies a value for a variable a template declares
- **THEN** the rendered output uses that value
- **AND** a variable the spec does not supply keeps its declared default

#### Scenario: A spec field the template does not declare
- **WHEN** a spec carries a field the chosen template does not declare
- **THEN** the field is ignored
- **AND** the render does not fail

#### Scenario: Same spec, same composition
- **WHEN** the same spec is composed twice on the same image
- **THEN** the two compositions are identical
