## 4. Visual Studio workflow

- [x] 4.1 Add an agent branch beside `if_raster`/`if_video`: an HTTP Request posting the request `CONTENT` (the brief) and a run-scoped `session_id` to the session, a fetch of the artifact as a file, and a `agent_result` node shaping the asset with content + `CONTENT_TYPE`; verify the branch fires only for `AUTHOR === 'agent'`, that no markup crosses it, and that a failed fetch yields that asset's `ERROR` only (implemented as `if_agent` off `parse_registry` → `build_author_brief` → `execute_author` → `fetch_artifact` → `agent_result` → `merge_branches`, with `merge_assets` skipping agent types so they are not emitted twice; `test_visual_studio_agent_author.py` asserts the routing, the brief-only payload, and the continued-error handling. **Two defects were found only by running it live:** `agent_result` (and `video_result`) read the fetched bytes as `binary.data.data`, but this instance stores binaries out of band (`data: "database"`, `id: "database:<id>"`), so the asset's data URL was `…;base64,database` and Slack received a 6-byte file — both now use `await this.helpers.getBinaryDataBuffer(0, 'data')`, with a regression test. And `execute_author`'s HTTP timeout was raised 600000 → 1200000 ms, because a slow model run exceeded 10 minutes and the client disconnect cancelled the turn). **A third live finding was pacing:** the agent authored a 3 s clip of many 0.4-0.5 s tweens, which at 8 fps read as a rapid flash. The clip's duration and frame budget are now request data (`durationSeconds`, `frames`) driven by the registry, and the brief asks for slow, deliberate motion; `diagram_agent` declares `durationSeconds: 18`, giving 24 frames at 1.33 fps. The adapter computes the rate as frames/duration, so a type is retuned from the registry alone — no future image change. **A fourth live finding came from the first 18 s run:** the agent spent its whole turn on two avoidable things. With no ability to view images it wrote seven puppeteer scripts to measure the layout (flaky CDP timeouts, ~18 min of the turn), and it kept trying to run the render in the background, where `hyperframes` aborts with `render_cancelled_parent_exited` the moment the parent shell exits — so `out.mp4` was never complete when the turn ended and the artifact fetch 404'd. The brief and `authoring.md` now state that the model cannot see images (do not screenshot and do not write browser scripts; rely on `hyperframes lint`) and that the render must run in the foreground and be waited for. `execute_author`'s 1200000 ms timeout is unchanged: the render itself is ~27 s for an 18 s clip, so the turn fits once the probing is gone
