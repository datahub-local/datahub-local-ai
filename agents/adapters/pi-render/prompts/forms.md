# Choosing the shape before the storyboard

The instruction above says how to answer. This file says what a form option carries, so a
caller can choose the kind of visual before it pays for a storyboard.

## The object

```json
{
  "options": [
    {
      "id": "announcement",
      "form": "launch",
      "why": "the post announces something we ship, with its features",
      "sketch": "a status badge, one headline, three feature chips and an interface window"
    }
  ]
}
```

## The fields

- `id` is a short, unique name for the option, so a critic can name it back.
- `form` is one id from the form vocabulary the brief carries. Do not invent a form and do
  not use `auto`: this turn's job is to settle on candidates.
- `why` is one line on why **this content** needs that shape, not what the shape is.
- `sketch` is one line on the composition: what is on screen, in what arrangement.

## What makes an option good

- Each option answers the brief the caller sent, including the person's requirements and
  any correction it carried. Do not propose a shape the content cannot fill.
- The options differ in composition. Two posters with different headlines are one option.
- A sequence, a mechanism or a failure over time needs a shape with scenes; a whole
  argument on one page needs `poster`; a structure needs `diagram`; a measured comparison
  needs `chart` or `data`. The vocabulary beside the brief defines each form.
- Name the shape the post's own announcement calls for. A post that announces a release
  and lists seven sources, a loop and a measured gain is not one claim.
